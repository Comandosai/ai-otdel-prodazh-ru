# Продажи: свежие поводы

## Что делает

Ищет **причину написать именно сейчас**. Письмо без повода это спам, письмо с поводом это деловое сообщение. Разница не в тексте, а в том, есть ли у тебя факт, объясняющий, почему письмо пришло сегодня.

Скилл собирает поводы четырёх типов и раскладывает их по компаниям из базы.

## Когда вызывать

- перед `/продажи письмо`, чтобы у писем был повод
- на регулярной основе, если конвейер работает еженедельно
- когда человек спрашивает, кто появился в нише за последнее время

## Четыре источника поводов, все бесплатные

### Повод 1. Новые в реестре МСП

Поле `is_new` из выборки. Признак «вновь созданный субъект» в смысле 209-ФЗ, то есть зарегистрирован в текущем календарном году.

Живые числа: регион 16, юрлица, ОКВЭД 49.41 → **177** новых. Регион 16, все ОКВЭД → **2660** новых.

**Ограничение по свежести, скажи о нём человеку сразу.** Реестр МСП обновляется **10-го числа каждого месяца**. Значит `is_new` и `dt_registry` дают дискретность **месяц, а не день**. Для еженедельного конвейера этого достаточно. Для ежедневного нужен повод 2.

### Повод 2. Дельта между срезами по ИНН

Самый сильный из доступных поводов, потому что он даёт **дневную дискретность** там, где у ФНС её нет.

Механика простая: `/продажи список` при каждом прогоне кладёт срез в таблицу **`snapshots`** (`dt_srez`, `inn`, `okved`, `employees`, `has_contracts`, `is_new`). Ты берёшь два последних среза и считаешь разницу.

Что ловит дельта:

| Изменение | Что это значит | Насколько сильный повод |
|---|---|---|
| **новый ИНН** в срезе | компания появилась в нише | сильный |
| **сменился `okved`** | компания перепрофилировалась | сильный, повод очень конкретный |
| **`employees` вырос** | компания растёт, объёмы растут | сильный для перевозчика |
| **`employees` упал** | сжимается | слабый, писать про это бестактно |
| **`has_contracts` стал 1** | компания зашла в госзаказ | сильный, у неё появились обязательства по срокам |
| **ИНН пропал из среза** | вышла из реестра МСП | не повод для письма, повод для отсева |

Дельта ловит не только новые регистрации, но и смену ОКВЭД, и возврат в реестр. Для лидогенерации это полезнее, чем чистые новые регистрации.

Важно: **серверного фильтра «зарегистрированы за последние N дней» у ФНС нет ни в одном из проверенных сервисов.** Ни в реестре МСП, ни в ЕГРЮЛ, ни в ГИР БО. Дата видна в выдаче, но фильтровать по ней приходится на клиенте. Поэтому дифф срезов это не костыль, а единственный рабочий способ.

Если срез в базе только один, дельту посчитать нельзя. Скажи об этом прямо: «первый срез записан, дельта появится со второго прогона». Не притворяйся, что нашёл изменения.

### Повод 3. Признак госконтрактов

Поле `has_contracts` из реестра МСП. Булев флаг «у компании есть госконтракты».

Это **бесплатная замена недоступному ЕИС**. Он не говорит, какой контракт и на сколько, но для повода этого хватает: компания, работающая с госзаказом, имеет закупочные процедуры, бюджет и жёсткие сроки поставки. Для транспортной компании это прямое попадание.

### Повод 4. Состояние сайта

Из фактов, собранных на обогащении: нет Яндекс.Метрики, копирайт двух-трёхлетней давности, нет адаптива, нет формы заявки, нет SSL, медленный ответ.

Живой пример из разведки: производственный сайт с копирайтом **2020** и без Метрики. Сайт не трогали шесть лет и никто не считает заявки.

Осторожно с этим поводом: он про сайт, а конвейер продаёт перевозки. Использовать его как **повод написать** можно, как **аргумент в письме** обычно нельзя, получится нерелевантно. Решай по контексту ниши и предупреди человека.

## Что требует российского IP, скажи это честно

**Обязательный блок. Не обещай человеку того, что у него не заработает, и не скрывай то, что заработает.**

| Сигнал | Источник | Статус с зарубежного IP |
|---|---|---|
| Вакансии водителей и механиков | `api.hh.ru/vacancies` | **403 forbidden** |
| Карточка работодателя | `api.hh.ru/employers` | **403 forbidden** |
| Справочники hh (регионы, отрасли, роли) | `api.hh.ru/areas`, `/dictionaries`, `/industries` | **200, работают отовсюду** |
| Кто выиграл госконтракт | `zakupki.gov.ru` | TLS-хендшейк не проходит, геоблок |
| Торги и имущество | `torgi.gov.ru`, `spending.gov.ru` | то же |
| Альтернатива по закупкам | `clearspending.ru` | proof-of-work защита Anubis, скриптом не берётся |

Блокировка hh **поэндпоинтная**: справочники открыты всему миру, всё, что содержит данные, закрыто по географии. Значит справочную часть можно кэшировать откуда угодно, а поиск вакансий пойдёт только у человека в России.

**Диагностика по коду ответа hh, покажи её человеку:**

- **403 `forbidden`** значит вы не в России. Чинить нечего, это география
- **400 `bad_user_agent`** значит проблема в заголовке. hh **банит User-Agent из собственной документации**. Строка `MyApp/1.0 (my-app-feedback@example.com)` из примера в доках даёт 400. Нужен уникальный UA с реальным контактом, например `LeadRadar/1.0 (dmitriy@comandos.ai)`

Коды регионов hh **не совпадают с кодами ФНС**:

| Регион | код ФНС | area hh |
|---|---|---|
| Москва | 77 | **1** |
| Московская область | 50 | **2019** |
| Татарстан | 16 | **1624** |
| Казань | нет | **88** |

### Отдельно про приём «свой автопарк по вакансиям»

**hh не умеет искать по ИНН.** Связка «компания из ЕГРЮЛ ↔ работодатель на hh» возможна только по названию, а это ненадёжный матчинг.

Поэтому вакансии водителей это **понижающий балл, а не жёсткий фильтр**. Формулируй результат именно так: «вероятно, есть свой автопарк», а не «есть свой автопарк». Жёсткий и точный признак только один, и он бесплатный: собственный ОКВЭД `49.41` в реестре, его применяет `/продажи отсев`.

## Пошаговый алгоритм

1. Прочитай `companies` и `snapshots` из `data/leads.db`.
2. Посчитай **дельту** между двумя последними срезами по `inn`. Если срез один, честно скажи об этом.
3. Отбери компании с `is_new = 1`.
4. Отбери компании с `has_contracts = 1`, отдельно выдели тех, у кого этот флаг **появился** в последней дельте.
5. Подними из `enrichment` (колонка `facts_json`) технические признаки протухшего сайта.
6. Проверь доступность российских источников **одним пробным запросом**, а не пачкой:
   ```bash
   curl -s -o /dev/null -w '%{http_code}' 'https://api.hh.ru/vacancies?text=водитель&area=1624&per_page=1' \
     -H 'User-Agent: LeadRadar/1.0 (dmitriy@comandos.ai)'
   ```
   200 значит российский IP, работаем с вакансиями. 403 значит зарубежный, блок вакансий отключаем и **говорим об этом человеку**, а не молча пропускаем.
7. Разложи поводы по компаниям. У одной компании может быть несколько, отсортируй по силе повода.
8. Запиши поводы в таблицу **`signals`**, **по одной строке на один повод**:

| Колонка | Что кладёшь |
|---|---|
| `inn` | ключ компании |
| `name` | название, чтобы отчёт читался без джойна |
| `signal` | тип повода коротко: `novaya_v_reestre`, `smena_okved`, `rost_chislennosti`, `poyavilis_goskontrakty`, `protuhshiy_sayt` |
| `detail` | конкретика с числами: «численность выросла с 34 до 61 за месяц» |
| `severity` | сила повода: `high`, `medium`, `low` |
| `source` | откуда: `rmsp`, `delta`, `site` |
| `checked_at` | когда посчитано |

У одной компании может быть несколько строк, это нормально и правильно: отчёт группирует их сам.

9. Собери отчёт.

## Отчёт

**HTML руками не пиши**, его собирает `scripts/report.py` из таблицы `signals`.

```bash
PRODAZHI="$HOME/.claude/tools/prodazhi"; [ -d "$PRODAZHI/scripts" ] || PRODAZHI="$(pwd)"
python3 "$PRODAZHI/scripts/report.py" --db data/leads.db --out out --only signaly
open out/signaly.html
```

Это **отчёт шага 4 из 5**. Генератор сгруппирует поводы по типу и отсортирует по `severity`, поэтому качество отчёта держится на поле `detail`: пиши туда числа и даты, а не общие формулировки.

**Блок про недоступное с этого IP покажи сам, в чате**, отдельно от отчёта: какие источники не проверялись и почему это география, а не поломка. Этот блок обязателен, даже если пуст.

## Какие скрипты запускает

| Скрипт | Роль |
|---|---|
| `scripts/fns_rmsp.py` | новый срез в `snapshots`, если сегодняшнего ещё нет |

Дельта и разбор поводов делаются запросами к `data/leads.db`, отдельный скрипт для этого не нужен. Отчёт собирает `scripts/report.py`.

Если в репозитории появится `scripts/hh_vacancies.py`, проверь его через `grep -n 'argparse' scripts/hh_vacancies.py`, а **не через `--help`**, и запускай только при подтверждённом российском IP.

## Что показывает человеку

- сколько компаний получили повод и сколько остались без повода
- **топ поводов** одной строкой каждый, человеческим языком
- какие два среза сравнивались и с какой датой
- **честный список недоступного с текущего IP**, с объяснением, что это география, а не поломка
- напоминание: реестр обновляется 10-го числа, поэтому `is_new` это месячная дискретность
- напоминание: вакансии дают вероятностный признак, потому что hh не ищет по ИНН
- ссылку на `out/signaly.html`
- следующий шаг: `/продажи письмо`

## Возможные ошибки и что делать

| Симптом | Причина | Что делать |
|---|---|---|
| Дельта пустая | в базе один срез | так и скажи: дельта появится со второго прогона. Не выдумывай изменения |
| Дельта показывает сотни новых | сравниваются срезы разных ниш или разных регионов | сравнивай срезы с одинаковыми параметрами выборки, иначе разница бессмысленна |
| `is_new` не меняется неделями | реестр обновляется 10-го числа | это норма, не баг. Дневную дискретность даёт только дельта срезов |
| hh отдаёт 403 | зарубежный IP | блок вакансий отключить, сказать человеку прямо. Чинить нечего |
| hh отдаёт 400 `bad_user_agent` | взят UA из документации hh, он в чёрном списке | поставь уникальный UA с реальным контактом |
| Вакансии нашлись не у той компании | hh не ищет по ИНН, матчинг по названию | понижающий балл, а не факт. В письмо это утверждение не ставить |
| `zakupki.gov.ru` висит и отваливается по таймауту | геоблок на уровне TLS, TCP при этом открывается | не лечится ретраями. Используй `has_contracts` из реестра МСП |
| Хочется взять закупки через clearspending | там proof-of-work Anubis | скриптом не берётся, нужен браузер. Не трать на это время |
| У всех компаний одинаковый повод | взят только `is_new` | добавь дельту и `has_contracts`, иначе письма будут выглядеть одинаково |
